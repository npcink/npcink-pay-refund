# 1.3.11 维护候选与验收

日期：2026-11-26。1.3.11 是包含后续维护的独立候选，不是已发布版本。原 1.3.10 ZIP 及其商户确认保留，两套制品的证据不互用。

## 逐项处置

- **H2**：已补[支付宝商户取证清单](REFUND-INTEGRATION-CHECKLIST.md#h2-alipay-request-number-conflict-evidence)，尚无真实冲突案例；不更改请求号策略，不在客户订单上试错。
- **L1**：查询、退款按钮、记录队列、设置页和 CSV 表头的动态文案接入现有文本域，更新 POT。使用完整句子和可重排占位符；退款渠道存储值、请求参数和 CSV 数据不翻译。在隔离站验证默认文案和 `en_GB` 合成词表，确认后台标题、分页语序、渠道显示及 CSV 标签可翻译。POT 是词条模板，不是完整英文语言包。
- **L7**：模拟微信已成功、本地已记账、待处理选项删除失败。保留同一个请求号，提示已记账但待处理状态未清；同号核对可补清理，不再次退款。
- **L8**：用锁定 EasySDK 和两个合成配置证实同一 PHP 请求中的全局 Factory 保留首个配置。未证实商户站点有共享同一类的第二个插件；未改 SDK 封装。若确认共存，再用隔离环境覆盖两种加载顺序、独立签名器和同号对账后评审隔离方案。
- **L9**：已验证旧存量退款窗口 `0` 仍回落到 7 天而非无限制，最小有效值为 1 天；卸载开关的显式零值仍由原回归覆盖。不全局改变 `empty()` 的含义。

## 限流设计：未实施运行时限制

1. 先在经授权站点统计脱敏的查询、新退款和退款状态请求频次、重叠峰值及轮询周期。没有真实分布前不设硬阈值，不收集完整订单号或网关正文。
2. 权限与 nonce 通过后，按站点、操作者和动作分开计量。新增退款与查询/核对使用独立预算；保护创建新退款的路径不能把已经提交的退款变成无法核对。限流不替代订单权限、退款锁或请求号幂等性。
3. 跨 PHP 进程用经过原子性验证的共享计数器，明确窗口过期和计数存储故障时各动作的行为。超限用 `429` 和可重试等待时间；前端不因此自动重提退款。先仅观察，再以独立开关试点。
4. 启用前验证跨进程并发、窗口过期、站点和操作者隔离、计数故障和回滚。关键验收：把新退款额度用完后，原请求仍能同号查询、确认和补记；无权或坏 nonce 的请求不扣减其他人的额度。

## 桌面 Excel 与发布门禁

- `node tests/csv-export.cjs /absolute/path/refund-excel-fixture.csv` 使用实际前端导出逻辑生成合成样表。签收时在选定候选的隔离安装上用同类数据导出，记录版本及 ZIP SHA-256。
- 在桌面 Excel 记录版本、系统和区域设置，分别直接打开及从「文本/CSV」导入。核对 UTF-8 中文、引号、跨行备注、列序，以及 `= + - @` 前缀值未当成公式；分别记录两种入口的前导零和超过 15 位订单号。若双击时自动转数值，不算完整保真；导入时将订单号列显式设为文本，再核对原值。
- 桌面 Excel 和支付宝、微信商户确认均待取得。签收必须对应同一个新候选 ZIP，不能由 CI、Chrome、CSV 单测或旧包商户验收代替。发布须另获明确授权，随后回读 GitHub Release 和 WordPress.org 下载制品。
