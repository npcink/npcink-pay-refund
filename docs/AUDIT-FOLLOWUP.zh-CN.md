## 操作日志与限流

- 在服务器 PHP 日志中按 `Npcink_Pay_Refund operation ` 前缀查找 JSON。事件含站点 ID、操作者 ID、UTC 时间和动作；支付事件另含 PHP 响应结果、HTTP 状态和订单的 HMAC 引用。引用依赖站点的 WordPress `auth` salt，轮换后不可直接与旧引用关联。不要向用户公开日志或站点 salt。
- 支付日志记的是已过 nonce 和权限检查的 AJAX 响应；`success` 也可能是处理中、补记提示或查询成功，不能替代提供方状态和已确认退款记录。导出只记服务器返回结果、行数及是否截断，不证明浏览器已保存文件。授权事件记录插件配置和迁移造成的直接权限变化，不覆盖外部角色编辑或卸载。
- 日志不含原始订单号、原因、姓名、密钥、支付响应、导出行或 SQL 错误正文。操作者 ID 仍是敏感信息：部署前确认日志写到非公开位置，并由站点维护者设置访问权限、轮换和保留期。这不是写入失败可补偿或不可篡改的审计存储；PHP 日志未可靠采集就不能作为完整取证记录。
- 先观察商户的查询突发、正常退款频次和状态查询频率；确需限流时按站点、用户和动作分别设门槛，用跨 PHP 进程的原子计数，并验证并发、失效和 `429` 回退。新退款与查询/对账不共用额度，避免超限阻断已提交退款的状态恢复。日志和未来的限流都不能替代订单级授权。

- 收尾回读：[GitHub CI 45772271216](https://github.com/npcink/npcink-pay-refund/actions/runs/45772271216) 的 `headSha` 对应 `433ad1b`，PHP 8.1 / WordPress 6.0 和 PHP 8.4 / WordPress 两组都通过。这是工程验证，不是该提交的商户验收。
